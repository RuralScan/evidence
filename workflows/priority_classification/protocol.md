# Bounded T5 documentation review protocol v0.1.0

Scope: drought_hazard, water_stress, iplc_lands and carbon_sequestration_potential. Reuse the five existing packets; admit at most two additional primary documentation sources to resolve binding semantics. This is not an all-T5 systematic review, a T4/effect sweep, dataset ingestion or a pilot calibration.

1. Audit quantity, native support, period, unit, derivation and existing T1/BIND metadata before reading thresholds. The method audit covers all 19 T5 variables. This batch investigates four; descriptors remain unscored.
2. Reopen the five authoritative URLs, verify cached bytes against their packet hashes and inspect relevant PDF tables visually. Search provider/title-specific queries to find corrections, versions or primary documentation. Prefer original methods over secondary descriptions. Cap this pass at seven sources; stop when each retained source has an identity, locator and explicit classification implication or hold. A failed direct request is an access hold, never evidence of paywall.
3. Screen visible search results for source authority, exact product/edition relevance and incremental information. Log queries, visible result counts, reuse, exclusion and deferred follow-up. Do not imply provider-wide result counts or per-query counts when the search interface returns a combined list. Do not stamp SRCH or the practice/family ledger from this cross-cutting search.
4. Reuse acquisition `verify_metadata` and `verify_document`: DOI round-trip plus opening-title check, or publisher-domain title verification for DOI-less documents. Preserve candidate, plan, receipt and artefact digest. Local originals remain private. PDFs require actual team-library accession before canonical registration; web sources require a team-retrievable archived snapshot. Search and extraction candidates may remain reviewable with those holds.
5. Extract source definitions and category boundaries, units, support, period, domain and caveats into separate findings. Keep a short exact excerpt and complete page/table/section locator so reviewers can read context. Separate provider statements from agent inference. Broad applicability does not prove a narrow target context.
6. Record six-axis credibility and provider independence limitations. Documentation is authoritative for product definitions, not automatically independent evidence of model performance or locally appropriate priority classes.
7. In method, propose source-class → decision-class interpretation and alternatives. Thresholds are default; terciles require an explicit pinned reference population. No quintiles, invented none, silent five-to-four collapse, binary severity gradient, stock-as-potential conversion or descriptor scoring.
8. Validate candidates and dependency hashes, then open reviewable PRs. An authenticated source-finding review must bind exact finding bytes. A separate method decision binds the complete classification/context hash. No agent votes. Accepted source findings alone do not authorize classification, release or runtime adoption.

Retry and history: stage the same content to the same content-addressed bundle; changed bytes produce a new proposal. Never overwrite a historical packet, proposal or review event. Hold/drop records remain available. The first implementation checks candidate intake and review replay with synthetic fixtures; production registration/adoption stays disabled until its schema and authorization adapter are accepted.

The archived snapshot of this protocol is pinned by SHA-256 in the batch. Runtime issue #12 remains the integration reference; this review edits neither runtime nor T2.
